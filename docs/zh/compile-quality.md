# 编译产出质量基线（compile yield）

> 度量对象：`memory_compile` 的用户通道 —— 一句真实口语能编译出什么事实。
> 为什么需要它：本项目承诺"陪伴型 AI 记住你"，但在 2026-09-23 之前这个承诺**从未被量化**：
> fixture 只有几百字节，没有任何测试衡量过真实口语的产出质量。前三轮评审发现的每个严重缺陷
> （变迁类型不可达、证据表从未写入、否定丢失）根因都是同一句：**代码从未在真实数据上跑过**。

## 1. 怎么跑

```bash
cargo test --test compile_yield -- --nocapture
```

报告通过 `tracing` 输出（`must_catch` / `should_catch` recall、幻影行数、过度抽取条数，以及每条
未命中的原句）。测试同时锁住不变量与回归下限，**掉了就红**：

- 每个事实必须携带原句（`payload.content`）与可回溯证据锚点（`payload.evidence`）；
- 同一句话编译两次必须字节级一致；
- 寒暄/噪声行产出任何事实都算幻影（当前 0/9）；
- 否定句不得存成肯定事实；
- `must_catch` recall 不得低于基线（见 §3）。

语料在 `tests/fixtures/compile_yield_zh.json`，加行即扩面，不用改代码。

## 2. 标注口径（三层）

| tier | 含义 | 用途 |
|---|---|---|
| `must_catch` | 当前机制（observation marker 表）**明确设计要命中**的表达 | 回归下限 |
| `should_catch` | 人类期望被记住、但当前机制可能覆盖不到的表达 | 度量能力缺口 |
| `must_ignore` | 寒暄与噪声 | 幻影率 |

## 3. 基线（2026-09-24，53 行语料 / 9 个会话 + 7 条承诺用例）

| 指标 | 值 |
|---|---|
| `must_catch` recall | **38/38 = 100%** |
| `should_catch` recall | **2/6 = 33%** |
| 幻影（噪声行产出事实） | **0/9** |
| 过度抽取（类型不在标注内） | 6 条 |
| 承诺抽取（`src/commitment.rs`） | 7/7 完全符合标注（含 3 条**必须不产出**的否定承诺） |

对照 2026-09-23 的首次基线（`must_catch` 30/30、`should_catch` 2/9 = 22%）：新增的
`should_catch` 行全部落在"通道缺口"上，补上自述通道后 `must_catch` 增到 38 行仍为 100%，
`should_catch` 缺口从 7 条收到 **4 条且只剩一类**。

## 4. 能力缺口（`should_catch` 仍漏 4 条）

这 4 条**不是引擎缺陷**，而是"默认词表的覆盖边界 + 一项未做的新能力"。按设计，**词表是用户的**
（默认表只作参考，用户用 `config/*.user.json` 增减；见
[configuration.md](./configuration.md) 的「资源文件（`config/`）」与 README 的「自定义词表」）：

| 语料 | 现状 | 需要什么 |
|---|---|---|
| "我妈下周要做手术，我得请假回去一趟" | 产出 `relationship(妈)`（可用但不是重点） | **新能力**：事件模板（人物 + 动作 + 时间） |
| "房东突然说要涨租，一下子多八百" | 零产出 | **新能力**：事件模板（主体 + 动作 + 数量） |
| "最近不太想出门，只想躺着" | 零产出 | **词表**：`{"want": ["想出门", "只想躺"]}` 一行即可覆盖 |
| "别再劝我早睡了，我做不到" | 零产出 | 无任何显式线索，属最难的一类，默认不追求 |

前两条要的是结构化模板抽取（新能力），不是词表：`FactType::Event` 已经有落点
（`cognitive_context` 的 `recent_events`），只是 `state_timeline`（区间/变迁视图）没有事件维——
事件是"点"而不是"状态"，没有维度是合理的。要不要做模板抽取属产品决定，**本轮不做**。

已修复的缺口（2026-09-23 → 09-24）：

1. ✅ **身份 / 关系 / 兴趣 / 习惯**：新增 `src/self_disclosure.rs` 自述通道
   （名字/年龄/职业/城市 → `Identity` + `attribute`；家人/宠物 → `Relationship` + `target`；
   爱好 → `Interest`；习惯 → `Habit`）。闭合词表 + 显式线索，取不到合格值就不产出事实。

## 5. 过度抽取的 6 条（已逐条核查，均非 bug）

| 事实 | 原因 | 处置 |
|---|---|---|
| `I'm so tired today…` → event | "think" 命中 `belief`，而 `belief` 在 `OBSERVATION_ACTIONS` 里**显式**声明为 Event | 记录：模型没有 belief 维度，映射到 Event 是明确选择，不再靠 `_` 兜底 |
| `我不喜欢应酬…` → emotion | "应酬" 同时在 `feel` 词表里 | 一条话产出 preference + emotion 两条，可接受 |
| `现在真的受不了加班文化了` → event | "受不了" 命中 dislike，另有 belief 路径 | 同上 |
| `我妈下周要做手术…` → relationship | 自述通道命中家人词"妈" | 正确（用户确实有母亲），只是没覆盖到重点的事件 |
| `我妹妹考上研究生了…` → relationship | 同上 | 同上 |
| `我的爱好是拍照，喜欢拍街景` → preference | "喜欢" 命中 marker 表 | 一条话同时给 interest + preference，符合预期 |

标注只写"期望出现的类型"，因此**额外产出≠错误**；本表的作用是把每一类额外产出都归因清楚，
避免把"设计使然"当成缺陷。

## 6. 结论与下一步

- 显式信号已 **100%**（38/38）：继续加同义词收益递减，且推高幻影风险——因此引擎
  **不再自带越来越大的词表**：默认表只是参考，领域词由用户在 `config/*.user.json` 里补，
  误报词用 `_remove` 关掉，反馈靠 `mnemosyne config-check`（打印生效词数/被删/被忽略条目，
  词表有问题时退出码非 0）。
- 剩余缺口**只剩一类**：**间接事件模板**（"房东突然说要涨租"、"我妈下周做手术"），
  属新抽取能力而非词表，**先记录、不擅自加**（见 §4）。
- 任何改动词表或抽取规则的 PR，跑一次 `mnemosyne config-check` 与本度量，就能知道
  "词表有没有写错"以及"有没有把显性信号弄丢"。
