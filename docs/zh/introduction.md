# Cognitive Memory MCP Server — 介绍

## 什么是 Memory Distillation？

**Memory Distillation** 是一个基于模型上下文协议（MCP）的服务器，为 AI 编程助手提供**持久的长期记忆**。与仅在单次会话内保留信息的上下文压缩技术不同，Memory Distillation 从对话中提取、分类并持久化知识，使 Agent 能够在未来的会话中回忆起这些知识——跨越数天、数周甚至数月。

### 问题：不会学习的 Agent

当前的 AI 编程助手有一个根本性的局限：

| 方案 | 做什么 | 会话结束后 |
|---|---|---|
| 内置上下文压缩 | 将当前对话保持在 Token 窗口内 | **全部遗忘** |
| RTK（精简 Token） | 压缩 Shell 输出 | **全部遗忘** |
| **Memory Distillation** | 提取并持久化知识 | **仍然记得** |

结果是：用户同一个问题问两次，就要付两次 Token 费用。Agent 没有办法将经验、偏好或决策从一个会话带到下一个。

### 解决方案：蒸馏即学习

Memory Distillation 将每次对话视为一次学习机会。在一个会话结束时——或按需触发——它运行一个 8 阶段流水线：

1. **提取** — 从对话中提取问题-解决方案对
2. **分类** — 将每对分类为知识、技能、偏好、经验、交互或个人档案
3. **评分** — 评估重要性，让闲聊内容自然地被降低优先级
4. **过滤** — 过滤掉噪音、秘密和安全敏感内容
5. **压缩** — 压缩为紧凑的 `问题：解决方案` 格式
6. **嵌入** — 转换为向量（或回退到纯关键词模式，零 API 成本）
7. **冲突解决** — 使用余弦相似度检查与现有记忆的冲突
8. **持久化** — 按租户进行容量控制和 LRU 淘汰

当新会话开始时，相关的记忆会被注入到 Agent 的上下文中——它知道自己之前学到过什么，无需浪费 Token 重新发现。

## 核心设计原则

### 1. 零成本关键词模式

服务器在启动时无需任何 API 依赖。设置 `--embedding-provider none` 和 `--retrieval-mode keyword`——不需要 API Key、不需要嵌入模型、不需要向量数据库。SQLite FTS5 提供全文本搜索，持续运行零成本。向量搜索是可选的升级，不是必需条件。

### 2. 确定性流水线

蒸馏流水线的每个阶段都是确定性的——不调用 LLM、不随机采样、无不确定性的启发式规则。这使系统**可测试、可预测、可审计**。相同的输入总是产生相同的输出。

### 3. 租户隔离

从底层设计就支持多租户场景。每条记忆都限定在租户 ID 范围内，检索时按租户过滤，容量限制（默认每种类型每租户 5000 条）对每个租户独立执行。

### 4. MCP 原生

实现了标准的模型上下文协议（MCP），使用 stdio 传输。与任何 MCP 客户端兼容——Claude Desktop、VS Code 扩展、自定义工具链——零集成阻力。

## 这不是什么

- **不是**上下文压缩的替代品——它是**长期记忆**，用于补充压缩
- **不是**LLM 代理——它不处理任何 LLM 推理
- **不是**通用数据库——它是专为 Agent 记忆构建的
- **不是**仅限云端——完全可以在本地运行

## 使用场景

| 场景 | 收益 |
|---|---|
| **软件开发** | Agent 跨会话记住项目约定、历史 Bug 修复、架构决策 |
| **DevOps / SRE** | Agent 回忆事件响应流程、Runbook 决策、环境特性 |
| **数据分析** | Agent 保留分析模式、库偏好、领域知识 |
| **个人助手** | Agent 记住用户偏好、常见任务、工作流习惯 |
| **研究** | Agent 从探索会话中构建持久的知识库 |
